# Snapmaker U1

Create the requested shape and a reviewable U1 print project. Distinguish visual acceptance, mesh checks, a completed slice and physical print testing. A model file or attractive render alone establishes none of the later stages.

This skill uses the shared Agent Skills format; Codex metadata in `agents/openai.yaml` is optional. Read [platform setup](references/PLATFORMS.md) when installing or moving between agents or operating systems. Resolve helper paths relative to this skill directory. Use the interpreter and runtime paths in optional `local-runtime.json`; otherwise use `.venv/Scripts/python.exe` on Windows or `.venv/bin/python` on macOS/Linux, with `.runtime/` for local assets. Discover installed capabilities before promising inference, CAD or slicer operations. The CLI slicer currently targets U1 **0.4 mm** profiles and accepts an explicit executable and matching profiles directory.

Respect the user's local/cloud choice. With `execution_policy: local_only`, keep photos and generation prompts on the machine, including when a host image tool runs remotely. Public weight downloads are setup, not permission to upload photos. Missing local stages should be reported explicitly.

## Choose the route

- **Dimensioned parts, organizers, gifts, fidgets:** prefer parametric CAD with an available solid-modeling tool or installed Manifold Python kernel. Preserve editable source and units. See [the CAD example](examples/moon-jewelry-dish/README.md). When richer sketches/assemblies are useful, [optional SolidCraft MCP](references/SOLIDCRAFT.md) can supply CAD; it is not a required dependency or a replacement for U1 preparation. Check moving clearances and print a small fit coupon for mechanisms; do not infer physical motion from an animation.
- **Image-guided organic models:** read [image reconstruction](references/IMAGE_TO_3D.md). Local options are [TripoSR](references/LOCAL_ENGINE.md), a separately configured [Modly](references/MODLY.md) app, or the advanced [TRELLIS adapter](references/TRELLIS_RUNNER.md). These are candidates, not guaranteed likeness or commercial-service parity.
- **Text-guided organic models:** use a permitted reference-image generator followed by an available reconstruction engine; do not claim TripoSR accepts text directly. Keep generated references distinct from observed photos.
- **An overlapping photographic capture set:** use [Apple Object Capture](references/APPLE_CAPTURE.md). Sparse front/side portraits are references, not a complete photogrammetry capture set.
- **Background removal or on-device planning:** on macOS use the native helpers in [Apple tools](references/APPLE_NATIVE.md). On other systems use supplied transparency or the separately configured local human-segmentation model in [TripoSR](references/LOCAL_ENGINE.md). Ordinary agent planning remains available without Apple Foundation Models. These tools do not reconstruct detailed 3D geometry. Do not substitute a cloud service when a local stage is unavailable.
- **Existing Bambu/MakerWorld project:** follow [Bambu conversion](references/BAMBU_CONVERSION.md). The adapter supports editable projects with one to four ordinary logical filaments and one-to-one routing. Mixed colors, many-to-one routing and unsupported projects require a manual workflow.
- **Printer status or loaded-spool check:** use the optional [read-only printer check](references/PRINTER_CHECK.md). Use an IP provided by the user or obtained from their selected Orca device details when authorized; never scan the network or infer physical slots from a Full Spectrum palette. Keep decoded tag metadata separate from editable printer configuration. Missing/disabled sensors and missing RFID identity remain unknown for automated checks; configured values alone cannot turn them into a pass. This check cannot establish print readiness or calibrated colors.
- **Color printing:** read [Full Spectrum](references/FULL_SPECTRUM.md). STL is geometry-only. A GLB can store appearance but may contain no colors; inspect the actual asset. Standard Snapmaker Orca uses a compatible painted project 3MF for this workflow.
- **Online reference collection:** follow [reference provenance](references/WEB_REFERENCES.md). Provider options and source links are in [research](references/RESEARCH.md); documentation does not establish an authenticated integration.

Ask only for details that change the result: intended use, dimensions, desired form/body extent, critical fits/loads, actual filament family/nozzle, and whether accessories belong in the model. Preserve an accepted master. Use one job folder, with intermediate attempts and diagnostics under `.work/`; keep the final delivery to `project.3mf` and `PRINT_CARD.md` by default. Retain editable source there when needed, and export separate STL/GLB files only when requested or required by a downstream stage. Do not delete existing user files to tidy a delivery.

For a beginner or first-print request, read [the beginner guide](docs/BEGINNER_GUIDE.md). Explain the selected material, layer height, walls, infill and supports in plain language. Include a small-test/first-layer plan, actual native preview checks and a short troubleshooting path. Start with the relevant official preset; do not turn an advanced calibration, firmware edit, new CAD app or multicolor setup into a prerequisite for a simple print.

Printer API keys require verified HTTPS by default. Do not add `--allow-insecure-api-key` unless the user explicitly accepts plaintext credential transport for that target; a local-network authorization alone does not imply that acceptance. Certificate failures must not trigger an HTTP fallback.

## Images and likeness

Isolate the requested subject and inspect narrow gaps, hair, glasses, hands and clothing. Preserve original photos and preprocessing provenance. Background removal and sharpening do not recover hidden geometry. A single photo leaves the sides and back inferred; request real closer/side/back views when likeness needs them.

Preserve the requested full figure, torso or bust. Do not substitute a relief, silhouette, generic analytic head, image displacement or a diagnostic head crop for a full 360° subject. Generated additional angles remain inferred.

Render actual mesh front, both sides, back and three-quarter views with `scripts/u1_preview.py`. Inspect physical facial features with textures disabled. Sampling must be labeled. Obtain portrait likeness acceptance before substantial color conversion or final slicing. When a result is rejected, change the inputs or method rather than repeating the same failed route or claiming smoothing restored missing anatomy.

## Geometry and print plan

Preserve originals. Inspect and repair only unintended defects; record changes and recheck form. Confirm units, axis, dimensions, stable bed contact, thin features, disconnected shells, winding and self-intersections where supported. Do not remove all but the largest component without checking whether details or moving parts are intentional.

Run `scripts/u1_mesh_check.py` on every delivered STL. `scripts/u1_prepare.py` also screens the serialized STL/GLB bytes: float32 export can collapse triangles that passed an in-memory check. The bundled checker cannot certify likeness, self-intersections, strength or physical fit.

Use **Draft / Normal / Strong / Flexible** intent and current official material/process presets. Read [print planning](docs/PRINT_GUIDE.md) for infill, walls, orientation, supports and material tradeoffs. Compare actual viable slices for material/time savings; include multicolor purge/prime waste. Fit includes supports, brim, tower and toolhead clearance inside the actual U1 profile, not just the nominal 270 mm cube. For print-in-place mechanisms, preserve gaps and prevent brims/supports from fusing components.

Default to **one project containing all plates**, retaining separate editable objects/assemblies. Use `scripts/u1_project.py` for compact delivery. It accepts multiple STL/OBJ parts for native arrangement, or one reviewed native U1 3MF to compare its current layout with global packing. Offer **Keep plates / Combine if beneficial / Fewest plates**. Default to the balanced comparison: select packing only when actual all-plate filament, time and plate count do not worsen. An explicit time, filament or plate priority may accept a documented tradeoff. Combining plates is a layout operation, not a boolean union or scaling operation. Keep incompatible materials, bed temperatures or per-plate overrides separate; do not merge independently calibrated projects automatically.

Optimize placement and repeated startup/tower overhead first, keeping geometry, scale, build orientation, layer height, walls, infill, supports, flow limits and color recipes intact. The helper checks protected data on native round trips and totals each plate once, including duplicate-content plates. If savings need changed infill/support/orientation, evaluate bounded alternatives against the part's load/finish requirements and compare actual slices before selection; never promise unchanged physical strength from settings alone. Fewer plates can increase travel, tool changes, cooling problems or failure cost. Report these tradeoffs; do not report estimated savings when a slice/estimate is missing.

For process alternatives use `u1_project.py --constraints limits.json` with explicit minimum walls/infill, maximum layer height and the allowed infill patterns/densities or support styles. The total budget is at most six slices, including baseline/layout runs. Never lower the infill minimum just to obtain savings without an adequate use/load basis; with missing requirements, retain layout-only optimization. The helper preserves geometry, orientation, walls/shells, speed/flow and calibrated recipes, checks declared limits, then compares eligible candidates. Per-object process overrides and adaptive/range layers require manual constraint evaluation. It does not automatically generate adaptive layers, change support materials, remove necessary supports or certify equivalent physical strength/finish. Existing native projects reject conflicting intent/material/support flags rather than ignoring them.

## Color and slicing

Retain source appearance before converting it to native paint/part assignments. A generic 3MF palette, texture or render does not prove the slicer kept printable colors. Four physical filaments can produce additional apparent colors through Full Spectrum's optical layer mixing; do not invent recipes or promise exact RGB reproduction.

`scripts/u1_orca_colors.py` requires a fresh **single-filament, non-mixed** template. It deliberately rejects calibrated multi-filament templates; use native Orca matching while preserving their recipes. Do not present a job-specific calibrated-project rewrite as a general packaged capability.

Complete native Manual Match with the actual spools, review achievable colors, recompute purge values and save a matched project. Use the compatible installed Color Mixing process. The default `scripts/u1_slice.py` route applies single-filament overrides and rejects unmatched, generic/unrecognized, converted and multi-filament/mixed 3MF projects. The explicit `--preserve-project` route (used by `u1_project.py` for native projects) supplies no process/filament overrides, retains calibrated assignments, and requests all plates. Unmatched target colors still require native matching. Conversion strips stale G-code; a fresh U1 slice is required.

Imported templates/projects and selected slicing presets must have no post-processing commands. The helpers reject them before export or execution; remove unwanted commands in a reviewed copy rather than silently bypassing the check. Shared 3MF readers enforce archive/member limits and the color/Bambu XML readers reject DTDs/entities. These checks do not make arbitrary native slicer input safe or replace review of machine/filament G-code.

The local slicer never sends a print job. It checks explicit extrusion centerlines across all layers against the resolved profile polygon, exclusions and height, then renders actual toolpath top/isometric views with support and brim colors. Unsupported geometry/state or out-of-bounds paths prevents `slice_completed`; retain failed reports. For native multicolor exports, run `scripts/u1_gcode.py` with that project's resolved machine JSON without changing its mappings. Read [toolpath scope and commands](docs/PRINT_GUIDE.md#toolpath-review): custom start/end blocks, macros, bead width and toolhead clearance remain outside these checks.

A completed slice still needs layer/support/seam/clearance and material mapping review. On macOS, project export initializes AppKit/OpenGL for thumbnails: do not launch it in Codex's seatbelt sandbox, which can abort at `glfwInit`. Use approved normal app access or Terminal; dry runs remain available. After a native failure, stop the optimization sequence and inspect the error instead of repeating the same launch. Some older Orca builds reject their own 2.x exports due to a legacy version check; use `--allow-newer-file` only after verifying compatibility with the selected build, never as a blind retry. If UI automation fails, make bounded attempts, preserve errors and provide a concrete project plus the required manual step.

## Deliver

Link the single project and short print card; link previews and editable source from the card rather than adding every diagnostic to the top-level delivery. Include dimensions, intended use, filament identities, color/matching status, orientation, infill/walls/supports, verified plate count, measured slice comparisons and unresolved checks. Preserve the accepted master and expose its location. Report whether the object has been physically printed; CAD motion and topology checks are not physical validation.
